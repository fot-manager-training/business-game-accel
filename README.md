# zero. — Zero Human Company Workshop

Интерактивный PoC для акселератора: 10 столов, 10 автономных компаний, 60 агентов и общий рейтинг по чистой прибыли. Интерфейс на русском языке, светлый интерфейс с чёрными блоками, кислотно-жёлтыми акцентами и хромированной графикой, собственные пиксельные персонажи и офисы. LLM и внешние API не используются.

## Публичное демо · GitHub Pages

**[Открыть демо](https://fot-manager-training.github.io/business-game-accel/)**

Публикация выполняется автоматически при push в `main` через [GitHub Actions](https://github.com/fot-manager-training/business-game-accel/actions/workflows/pages.yml). В **Settings → Pages → Build and deployment** должен быть выбран **GitHub Actions**. Workflow устанавливает зависимости, проверяет финансовую модель, серверный режим и браузерное демо, загружает `dist-pages`, публикует Pages и проверяет доступность публичных HTML, JS, CSS и шрифта. Дополнительные токены и секреты не нужны: используются стандартные права `GITHUB_TOKEN` и OIDC.

GitHub Pages не запускает Node.js. В этом режиме симуляция полностью выполняется в браузере: у каждого посетителя **своя независимая игра**, без общего рейтинга между устройствами. Изменения переживают обновление страницы в той же вкладке благодаря `sessionStorage`; закрытие вкладки завершает локальную сессию. Если браузер запрещает хранилище, демо работает в памяти без сохранения. Таймер и экономика работают, пока страница открыта; время закрытой страницы не начисляется. Для совместного воркшопа на нескольких устройствах используйте серверный режим ниже.

Проверка статической сборки локально:

```sh
npm ci
npm run build:pages
npm run preview:pages
npm run test:pages
```

Демо доступно на порту **4173** под путём `/business-game-accel/`. `PAGES_BASE_PATH` меняет базовый путь для другого имени репозитория. `dist-pages` и `dist` разделены: серверная и статическая сборки не перезаписывают друг друга.

## Запуск

Требуется Node.js 22+ и npm. Проверено на Node.js 24.19.0.

```sh
cd /workspace/business-game-accel
npm ci
npm run dev
```

Vite слушает порт **5173**, сервер сессии — **3001**. Все клиенты одного сервера получают общее состояние через Server-Sent Events. В development Vite проксирует `/api` на сервер.

Сборка и запуск готового приложения:

```sh
npm run build
npm start
```

Готовое приложение и API обслуживаются одним процессом на порту **3001** (`PORT` переопределяет порт). Для доступа с разных устройств сервер должен быть доступен по сети; GitHub Pages публикует только отдельное браузерное демо.

## Онлайн-экран и пиксельный мир

Персонажи выполнены крупными прямоугольными блоками с разными костюмами для каждой роли. Над головами появляются диалоговые окна: сначала обращение к другому агенту и ответ, затем намерение «Иду…» с конкретной следующей задачей. Эти реплики формируются из реальных сообщений симуляции; новые сообщения заменяют предыдущие, пауза фиксирует текущую реплику.

Стартовый раздел **Онлайн** показывает все 10 пиксельных офисов и 60 агентов одновременно. Движущиеся пакеты обозначают сообщения: зелёные — внутри компании, голубые — между командами, жёлтые — оплату. Лента **Прямой эфир** показывает отправителя и получателя с номером стола, ролью агента, типом сообщения и временем.

- Каждые 5 секунд все активные компании передают внутренние задачи по цепочке CEO → Product → Developer → Marketing → Sales → Finance → CEO. Приостановленные агенты не отправляют эти сообщения.
- Перед автономной сделкой видны запрос, предложение, согласование задачи, передача результата на проверку и согласование оплаты. Сообщения выполнения и оплаты связаны с конкретным ID сделки; сумма оплаты совпадает с финансовым журналом.
- Фильтры позволяют выбрать команду и внутренние/A2A-сообщения. Нажатие на запись выделяет её связь на карте, нажатие на персонажа открывает карточку конкретного агента.
- Есть масштаб карты, полноэкранный режим для проектора и пауза. При паузе останавливаются сообщения и движение пакетов; системная настройка уменьшения анимации также учитывается.
- На мобильном карта прокручивается внутри своего блока, чтобы все персонажи оставались доступными. Пиксельные персонажи и рабочие места используются также в индивидуальном офисе и карточках агентов.

В Pages это взаимодействия десяти игровых команд **внутри сессии посетителя**. Серверная версия транслирует одну и ту же карту всем подключённым экранам через SSE.

## Как провести воркшоп

1. Первое включение показывает демонстрационную сессию с примером уже работающей экономики. Чтобы начать игру с равных ресурсов, откройте **Настройки сессии → Начать новую сессию**.
2. Выберите длительность (15–90 минут), создайте сессию и назначьте каждой команде её стол через список компаний. Новая сессия создаётся на паузе.
3. Нажмите **Продолжить**. Команды выбирают стратегии, инвестируют в продукт и взаимодействуют через A2A-маркет.
4. Таймер автоматически фиксирует результат. Организатор также может завершить игру досрочно. Результаты доступны в рейтинге и CSV.

Это демонстрационный общий пульт: **авторизация и разграничение команд отсутствуют**. Любой подключённый участник может управлять любой компанией и сессией. Перед использованием как публичной многопользовательской платформы нужны отдельные роли организатора/команды и контроль доступа на API. Данные и деньги игровые.

## Правила симуляции

- Стартовый капитал каждой компании — **100 000 ₽**. Прибыль = выручка − расходы; капитал = стартовый капитал + прибыль.
- У каждой компании 6 агентов: CEO, Product, Developer, Marketing, Sales, Finance.
- Каждые 5 реальных секунд активные агенты создают выручку и операционные расходы. Формулы детерминированы номером стола и циклом; случайный или LLM-вызов не выполняется.
- Стратегия «Рост» умножает базовую выручку на 1,42 и расходы на 1,6; «Эффективность» — на 0,84 и 0,56 соответственно. «Баланс» — базовые значения.
- Приостановка агента пропорционально уменьшает выручку и расходы, останавливает его счётчик задач.
- Инвестиция стоит **3 000 ₽** и добавляет 8 процентных пунктов к множителю выручки на дальнейшие циклы.
- Каждые 30 секунд агенты автоматически заключают одну A2A-сделку между компаниями по очереди; для этого у покупателя должны работать CEO и Sales, а у продавца — Sales. Также можно заказывать услуги вручную через A2A-маркет.
- Любая A2A-услуга стоит **1 200 ₽**: эта сумма становится расходом покупателя и выручкой продавца. Покупатель также получает +8 процентных пунктов к множителю выручки. Исполнение мгновенное; категории услуг в этом PoC имеют одинаковый эффект.
- Пауза останавливает таймер и автоматические циклы, но позволяет принимать управленческие решения. После финиша экономические изменения запрещены. Равные результаты отображаются в стабильном порядке столов, без дополнительного критерия победителя.

## Хранение и перезапуск

Состояние сохраняется атомарно в `.data/workshop.json` (игнорируется Git). После перезапуска восстанавливаются компании, время и статус. Время выключенного сервера не начисляется. `ZERO_DATA_DIR` позволяет выбрать отдельный каталог данных. Состояние рассчитано на **один процесс сервера**, без кластеризации. Сервер после перезапуска продолжит активную сессию, если она не была поставлена на паузу.

## Проверки

```sh
npm test          # финансовая модель, агенты, таймер, стратегии, A2A
npm run build    # production-сборка
npm run test:e2e # браузерные сценарии, отдельный сервер и данные в /tmp
```

Браузерные проверки используют системный `/usr/bin/chromium`. На другой машине укажите установленный браузер в `playwright.config.js` или установите Chromium через Playwright и уберите `executablePath`. Тестовый сервер работает на 3002, не меняя основную сессию.

Шрифт Manrope хранится локально в `src/assets/manrope.ttf`, лицензия — `public/manrope-license.txt`. Приложение после установки не требует внешних сетевых запросов. SVG-персонажи созданы для проекта; сайт digio.me не удалось открыть из среды, его материалы не использовались.
